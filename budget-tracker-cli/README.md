# Budget Tracker CLI

Итоговый проект по TypeScript: интерактивное консольное приложение для управления личными финансами. Домашние задания тем 1–12 сохранены отдельными версиями `topic-01`…`topic-12`; итоговая версия отмечена тегом `final-project`.

[Условие итогового задания](docs/assignments/final-project.pdf). [Условия тем 1–12](docs/assignments). [Исходный репозиторий курса](https://github.com/vovachebr/TypeScript-homeworks).

## Установка и запуск

Требуется **Node.js 22 или новее**, npm и обычный интерактивный терминал, например терминал WebStorm, PowerShell или Windows Terminal.

Из корня репозитория:

```sh
cd budget-tracker-cli
npm install
npm start
```

`npm start` запускает TypeScript через `tsx`. Главное меню начинает работу с пустым списком счетов.

Сборка и запуск JavaScript непосредственно в Node.js:

```sh
npm run build
npm run start:compiled
```

## Как пользоваться

Выбирайте пункты стрелками вверх/вниз и нажимайте Enter. Для подтверждения удаления введите `y`; Enter без ответа оставляет данные на месте. Ctrl+C завершает работу без стека ошибки.

1. В главном меню выберите **«Создать счёт»** и введите непустое название. Счёт получает UUID автоматически; откроется его меню.
2. **«Добавить транзакцию»** предлагает тип «Доход»/«Расход», сумму, дату и описание. Сумма должна быть положительной, допускается до двух знаков после точки или запятой. Дата — существующий календарный день в формате `ГГГГ-ММ-ДД`, по умолчанию сегодня. Описание обязательно.
3. После добавления приложение возвращается к счёту: видны список транзакций, доходы, расходы и баланс.
4. **«Удалить транзакцию»** предлагает список и пункт «Отмена». Запись удаляется только после отдельного подтверждения. Для пустого счёта выводится понятное сообщение.
5. **«Экспортировать в CSV»** запрашивает путь с расширением `.csv`. По умолчанию это `account-<UUID>.csv` в текущей папке. При наличии файла запрашивается подтверждение перезаписи. Ошибка записи отображается в меню счёта; приложение продолжает работу.
6. **«Удалить счёт»** запрашивает подтверждение и удаляет счёт вместе со всеми его транзакциями, затем возвращает к списку счетов.
7. **«Назад к списку счетов»** возвращает в главное меню. В нём можно выбрать любой существующий счёт, создать новый или выйти.

Данные хранятся в памяти до завершения приложения. Для выгрузки используется CSV; автоматическое сохранение и импорт не требуются в итоговом задании.

CSV содержит заголовки `id,amount,type,date,description`. Запятые, кавычки и переводы строк экранируются. Пустой счёт экспортируется с заголовками. Родительская папка файла должна существовать. Файлы с именем по умолчанию исключены из Git.

## Соответствие итоговому заданию

| Требование | Реализация | Проверка |
| --- | --- | --- |
| Главное меню, список счетов, выбор и выход | ApplicationController.run(), InquirerInteraction | Пустое меню, повторный выбор счёта, выход |
| Создание счёта с уникальным ID | Account и uuid | Создание, UUID, несколько независимых счетов |
| Просмотр счёта и транзакций | ApplicationController.showAccount(), Account.toString() | Список, сводка и возврат к списку счетов |
| Интерактивное добавление с валидацией | ApplicationController.addTransaction(), utils/validation.ts | Доход, расход, некорректные суммы, даты и пустой текст |
| Удаление транзакции с подтверждением | ApplicationController.removeTransaction() | Отмена выбора, отказ и подтверждение |
| Удаление счёта со всеми транзакциями | AccountManager.removeAccountById(), Account.clearTransactions() | Отказ сохраняет данные; подтверждение очищает счёт и его транзакции |
| Асинхронный экспорт CSV | Account.exportTransactionsToCSV() | Экранирование, пустой счёт, ошибка записи и перезапись |
| Весь ввод и подтверждения через inquirer | InquirerInteraction | Проверка list/input/confirm и отрицательного ответа по умолчанию |
| ООП, интерфейсы, типы, enum и строгая типизация | classes/, interfaces/, strict: true | Сборка TypeScript и отдельная проверка типов |
| console.clear(), навигация, обработка ошибок, README | ApplicationController и эта инструкция | Очистка при переходах, восстановление после ошибки, Ctrl+C |

В коде приложения нет явного `any`. Ранее выполненные декораторы сохранены; LogClass использует Proxy, сохраняя сигнатуру конструктора и метаданные. Технические логи декораторов отключены в интерактивном режиме, чтобы меню оставалось читаемым.

## Учебные примеры и проверки

```sh
npm run demo
npm test
```

`npm run demo` запускает учебные примеры из `src/demos/homework-demo.ts`: утилитные и mapped-типы, работу классов, логирование декораторов, защиту свойств и CSV. Этот пример создаёт `main_account.csv` и завершает работу.

`npm test` собирает проект, проверяет типы и запускает **12 автоматических сценариев** из `tests/controller.test.mjs` и `tests/runtime.test.mjs`. Проверки контроллера используют заранее заданные ответы через тот же интерфейс взаимодействия; реальное приложение получает ответы через `inquirer`. Ошибочные примеры в `tests/typecheck.ts` помечены `@ts-expect-error`, чтобы компилятор продолжал их отклонять.

## Структура проекта

```text
src/
├── index.ts                    # Запуск интерактивного приложения
├── classes/
│   ├── ApplicationController.ts # Навигация, формы, подтверждения, ошибки
│   ├── InquirerInteraction.ts   # Все запросы пользователю через inquirer
│   ├── AccountManager.ts
│   ├── Account.ts
│   └── Transaction.ts
├── interfaces/                 # Контракты, enum, утилитные и mapped-типы
├── decorators/                 # LogClass, LogMethod, ReadOnly, Metadata
├── utils/                      # Валидация, CSV, ошибки, управление логами
├── lib/                        # JavaScript-библиотека и собственные .d.ts
├── demos/
│   └── homework-demo.ts         # Примеры предыдущих домашних заданий
├── calculation-demo.ts
├── functions.ts
└── generics.ts
tests/
docs/assignments/
```

Контроллер отвечает за сценарии, классы Account/AccountManager — за данные и вычисления, InquirerInteraction — за запросы пользователю. Интерфейс IUserInteraction позволяет проверять навигацию без ручного ввода. Удаление связанных транзакций выполняется в AccountManager, поэтому правило действует и при использовании класса вне меню.

## Как открыть отдельное ДЗ

Из корня репозитория, например для темы 4:

```sh
git switch --detach topic-04
cd budget-tracker-cli
npm install
npm run build
npm start
```

Возврат к итоговому приложению из корня репозитория:

```sh
git switch master
cd budget-tracker-cli
npm install
npm start
```

Перед переключением сохраните собственные изменения. После переключения выполните `npm install`: зависимости разных этапов отличаются. Старые варианты types.ts, classes.ts и решения без классов сохранены в своих тегах.

Репозиторий для сдачи: https://github.com/ravenhaha/ts-course. Отдельная тема доступна, например, по адресу https://github.com/ravenhaha/ts-course/tree/topic-04/budget-tracker-cli.

## Уточнения к предыдущим условиям

- Тема 4: до появления класса Account используется IAccount, как в шаблоне преподавателя.
- Тема 5: ISummary содержит числовые итоги, а текстовая информация выводится через getSummaryString(). Сохранены оба имени getAccounts() и getAllAccounts(), встречающиеся в условиях.
- Тема 7: выполнен итоговый чек-лист с namespace, reference, module: none и outFile. TypeScript закреплён на 5.9.3, поскольку версия 7 удаляет необходимые настройки. В этом теге ранние демонстрации собираются отдельно через tsconfig.demos.json.
- Тема 8: выполнен переход на модули. Приватное _id с getter id совместимо с интерфейсами. Реализованы оба варианта имени библиотеки из условия: formatCurrency и budget-utils. Относительные .js-импорты и allowJs обеспечивают запуск сборки в Node.js.
- Тема 9: update() изменяет поля данных, сохраняя идентификатор и методы. Переименование счёта доступно в тегах тем 9–11.
- Тема 12: ReadOnly защищает id и name. Примеры попыток изменения находятся в demos/homework-demo.ts. useDefineForClassFields: false обеспечивает инициализацию через setter декоратора; описание transactions читается из reflect-metadata.
